# 分类关系后端接口

基础路径：`/api/classifications`

所有接口都需要：

```http
Authorization: Bearer <登录接口返回的 token>
```

分类、标签和由题目聚合出的知识点数据均按当前登录用户隔离。

## 接口列表

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/overview` | 一次返回分类树、分类列表、知识点、标签、难度分布和汇总数据 |
| POST | `/categories` | 新增分类 |
| PUT | `/categories/{id}` | 修改名称、描述、父级、状态和排序 |
| DELETE | `/categories/{id}` | 删除空分类；存在子分类或关联题目时拒绝 |
| POST | `/tags` | 新增标签 |
| PUT | `/tags/{id}` | 修改标签 |
| DELETE | `/tags/{id}` | 删除标签 |
| PUT | `/knowledge-points` | 重命名知识点，并同步更新关联题目 |
| DELETE | `/knowledge-points?name=...&subject=...` | 从关联题目中清除知识点，不删除题目 |

## 分类请求示例

```json
{
  "name": "数据库",
  "description": "数据库原理、SQL 与事务管理",
  "parentId": null,
  "active": true,
  "sortOrder": 10
}
```

分类最多可形成任意层级；后端会阻止把分类移动到自身或其子分类下。停用分类不能再绑定到新建、修改的题目。

## 标签请求示例

```json
{
  "name": "高频考点",
  "description": "考试中经常出现的内容"
}
```

## 知识点重命名示例

```json
{
  "oldName": "事务",
  "newName": "事务管理",
  "subject": "数据库"
}
```

## 数据库升级

- 全新数据库：执行 `backend/src/main/resources/db/schema.sql`
- 已初始化数据库：执行一次 `backend/src/main/resources/db/migration-classification-relations.sql`
